## 为什么改

此前更新分散在 CHANGELOG、版本说明和功能专题里，同一开发版本内的多次变化没有统一时间线，也没有检查保证每次都登记，难以回答“这次升级了什么”。

## 这次改了什么

- 从重构基线后的 Git 历史逐条回填 69 次迭代，分别说明问题、具体变化、实际验证和发布状态；没有验证证据的历史项明确标为未记录。
- GitHub 的 `docs/rag/README.md` 首页直接展示最近八次升级的具体变化，链接逐次详情；完整时间线按时间倒序展示所有记录和真实提交。首页与时间线自动同步，不只更新本地文档。
- RAG 支持查询最近升级和按原源码版本筛选，旧版记录不会被统一标成当前版。
- CI 检查新程序提交是否有对应升级记录，并检查必填内容和目录同步；原有功能专题继续描述当前行为。

## 验证记录

四项专项测试通过：历史版本与未验证状态保持准确、缺少内容或重复标识报错、漏记程序提交会失败且补记后通过。新增验证确保 GitHub RAG 首页漏掉最近变化时检查失败。实际查询正确返回最近升级，并将主多视图历史定位到 preview.3。历史覆盖检查实际发现一条新提交缺少记录，补记后复核；知识索引与时间线检查通过。未使用客户剧本或收费生成，未发布安装包。

## 发布状态

源码与项目文档更新；公共 preview.5 安装包不变。本记录随实现提交加入，确切提交号由 Git 文件历史确定。
