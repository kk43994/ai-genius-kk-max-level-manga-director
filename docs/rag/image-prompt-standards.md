# 图像制作提示词规范与实测记录

适用版本：0.3.0-preview.4。更新：2026-11-02。状态：持续实测，尚无跨多场景稳定性结论。

用户要求：效果好且稳定的生成方法应沉淀为规范，供之后制作复用。原始完整提示词、具体参数、参考图版本、返回图与审核意见留在对应项目任务中；本知识源只保存去除客户内容的结构、通用示例和结论。不能把一次好图、成功回执或合成测试写成稳定规范。

## 模型分工纠正（2026-11-02）

MJ 只用于探索人物、场景和美术风格；图片创作默认 Lib Image 2.5 Pro，并通过官方实时模型目录提供下拉选择。人物形象选定后，正式主多视图、剧情状态、场景、道具和分镜默认使用 Lib Image 2.5 Pro，用户可按用途改选。下文旧 Image2 的实测记录是历史证据，不代表 Image2.5 的效果已验收；结构模板迁移后需要重新检查输出。旧任务不换模型或清空回执。

## 记录与晋级

每条规范记录：编号与版本、用途、模型、画幅与数量、前置参考、固定内容、可替换变量、提示词结构、审核标准、失败模式、实测状态及证据位置。状态分为：待验证、单次通过、重复验证通过、停用。重复验证至少覆盖两次独立生成和两个适用实例，保留失败记录；这是项目的最小经验门槛，不构成成功率保证。

改提示词后新建版本，不覆盖旧记录。一次优先改变一个可判断的条件。失败图要记录是主体错、结构错、机位错、风格偏离还是细节缺失；按明确原因修改，避免只堆“高质量”等词。

## P-001：先说当前对象，再继承全剧美术规范

状态：真实前端测试中，人物、空场景与道具均恢复了正确主体；更广泛的稳定性待验证。MJ v8.1 用于基础形象或风格候选；Image2 用于规范资产。全剧规范不应混入当前对象正文开头。

顺序：

1. 本次只制作的具体对象与用途。
2. 必须保留的外形、材质、空间或身份。
3. 画面数量、视角、背景、构图。
4. 只针对当前任务的排除项。
5. 全剧美术规范放后面，仅继承适用的画风、材质、色彩与光线，不复制无关角色、服装、场景或视图。

失败修正：把包含全剧人物设定的风格正文放在最前面，曾使男性、场景和道具候选混入其他人物定妆内容。主体优先后重抽，真实图像检查确认主体恢复。已准备任务保持不可变，需要通过前端重新准备新任务才能应用新规范。

## P-002：场景四视图的空间坐标

状态：四视图已实际返回；一例火灾场景通过当前测试审核，另两例因门位置与重复机位退回。以下是基于实测修订的模板，仍需重复验证，不能标为稳定。

模型与输入：Image2，已审核的该场景 MJ 基础图，默认 16:9，一张包含四格的场景资产板。该场景的不同时间或受损状态先保留相同空间描述，再单独列出变化。图像来源必须明确；未实际绑定某张图时不能写成已参考该图。

可替换变量：场景类型、长宽关系、北/南/东/西墙特征、门窗位置、固定家具、主体活动区、时间、光线、受损状态。

```text
本次只制作【场景名称】的空间多视图。参考图只用于该空间的建筑、材质、家具和美术方向。
同一空间坐标：【北墙...；南墙...；西墙...；东墙...】。
固定物件：【物件A的位置、朝向、相对门窗关系】。中心【活动区】保持可供人物表演。
一张2×2四格，四格是同一空间的四种不同机位：
左上：从南向北的正面，清楚展示【北墙关键结构】。
右上：从北向南的180度反打，展示与正面相反的墙面和【主要家具背面】；不可重复正面或侧面。
左下：俯视，北朝上，北墙在上、南墙在下、西墙在左、东墙在右；门窗与家具位置严格对应。
右下：从东向西的侧面，展示【西墙关键结构】，与另外三格明显不同。
【时间、光线、状态】。四格内建筑尺寸、门窗数量与位置、家具外形、地面材质一致。
无人物、无文字标签、无额外门窗，不把四格画成四间相似但不同的房间。
最后继承本剧适用于场景的美术规范。
```

审核：正面与反打是否确实相差约180度；俯视是否把门从短墙移动到侧墙；侧面是否重复另一格；门窗数量、沙发/桌子朝向、动线与光源位置是否可互相解释。四格都好看但不能对应，不通过。

失败记录：

- 俯视把位于远端短墙的门画到长侧墙。修订为固定世界坐标，并逐格明确墙面位置；修订后新图待复核。
- 四格中的两个格子都是近似侧面，缺少反打。已在前端退回，明确家具在北侧、窗在西侧、电视墙在南侧，并要求反打看到家具背面。Pro 返修图已实际核对，正反打、俯视和侧面关系基本一致；属于单次通过，不能声称所有场景稳定。
- 火灾场景一例通过结构检查，但不能据此宣称其他场景的反打和俯视也稳定。

## P-003：角色主图与状态派生

状态：真实前端已检查3个角色主图及7个派生状态，作为当前分镜测试选用；不等于用户最终美术定稿。

主图：同一角色已审核的MJ基础形象 → Image2。默认16:9，一张正面全身、侧面全身、背面全身、头部特写的四视图，统一干净背景。先锁定脸、发际线、发长、体型、基础服装。

状态图：只绑定同一角色已审核主多视图 → Image2。提示词先写“保持参考主图身份与体型”，再列本次唯一状态变化，如服装、湿度、烟灰、表情。保留相同四视图布局；不要把当前人物状态画成场景群像。未受伤状态不得继承后来伤痕，换装不得换脸。

审核：逐一比对脸型、发型、体型、服装结构与剧情状态；主图未保留、来源是另一人物或另一状态图时，不能进入派生。

## P-004：道具白底正视图

状态：两件道具完成真实图片检查；新增两件不同 Pro 道具按白底净化模板分别返回完整单物体，无模型附加排版文字，均已通过前端测试选用。平台 AI 标识保持；仍不能据此宣称所有道具稳定。

模型与输入：Image2，已审核的该道具MJ形象，默认1:1，一张单物体白底图。固定轮廓、材质、连接关系、数量与开合状态；省略不需要的多视图。

模板：本次只制作【道具】；保留【轮廓/材质/连接结构】；一个完整物体居中，纯白背景，正视产品资产图；无手、人物、无关道具或模型自行编造的标题。参考图里模型生成的说明排版不作为物体设计依据；平台正常的AI生成标识保持。

审核：物体是否完整，是否多出同类物，连接处是否合理，关键细节是否清楚；手机屏幕等尚无确定剧情信息的部分不得编造日期、短信或标识。必须另行检查真实图像，不靠排除词推断已修好。

## 证据与使用入口

完整原始内容和具体任务回执保存在隔离验收实例，不进入Git。当前验收目录位于仓库同级的 `../live-instance`，截图位于 `../evidence`。正式使用时从工作台对应物料的任务、参考图和审核历史核对完整提示词；规范更新后不改变旧任务快照或自动批准旧图。

相关实现：`frontend/workflow/production-generation.js` 默认制作要求；`backend/generation/` 执行参考来源与提示词顺序；`frontend/workflow/controller.js` 费用确认和人工审核。知识源暂未自动注入全部模型提示词，采用规范时仍通过制作表单核对。


## P-005：多参考单镜头 Pro 分镜

状态：一个适用镜头的两组独立生成均返回可用画面，经本轮前端视觉检查选用一张；尚未覆盖第二个适用实例，不标为重复稳定。

参数：Lib Image 2.5 Pro（官方 modelId `lib-image-2.5-s`）、high、2K、9:16、每组 1 张，同时 2 组。本次实际回图为 1152×2048。每组独立回执，当前保留版本与其他历史候选分开。

结构：明确单镜画面，不画资产板；绑定本镜已固定的人物状态和场景版本，逐项说明参考承担的人物身份、服装状态或空间用途；描述景别、构图、人物相对位置、动作瞬间、表情与视线；光线沿用场景；无字幕和模型自编文字。原文对白留在分镜脚本内，不要求图片渲染长对白。

审核：多人物身份与服装是否分别正确；接触动作是否自然，手臂与手部是否可解释；场景与角色状态是否一致；镜头是否传达对应节拍。两张可以都可用，但当前镜头只选一个正式版本。一次参考融合成功不代表所有空间连续性或后续镜头都已通过。

## P-006：静帧必须继承已保存的首帧状态与连续性

状态：真实跨镜检查发现一张情绪与画风可用的画面把地面人物改成坐椅，并增加躯干绳索；已撤回此前测试选用，保留具体返修意见。返修后的真实回图已核对：脸部近景保留低位仰视，没有错误坐具或躯干绳索，已通过前端测试选用；其他相关镜头仍逐镜返修。

原因：独立的 `imagePrompt` 可以遗漏脚本其他字段已明确的身体位置与束缚状态。新的默认生成要求同时带上本镜 `framing`、`startState`、`continuity`；不直接加入 `endState`，避免把镜末获救或受伤状态提前画入首帧。已有手工草稿与已经准备的任务不自动改写，须在前端核对后重新准备。

审核要按连续镜头对照，不能只看单图是否漂亮。发现姿态或物件错误时，先在分镜提示词保存明确限制，再显式重做；旧审核历史仍保留。近景可通过明确裁切边界排除无关身体部位，但不能把画外状态标成已验证可见。


### P-006 补充：近景裁切与道具特写（2026-11-02）

Pro 真实回图新增两个适用实例：一张双人威胁近景保留低位角色与高位角色关系，器物与面部保留间隙；一张反应近景通过前景遮挡把画外动作留在画外。两张均无错误坐具或躯干束缚，已记录具体测试审核，但同批另一张道具微距仍擅自添加封口与躯干绳索，不能以两张通过宣称通用稳定。

道具特写若叙事重点为物证，明确“仅持物手指与物件入画，其他角色身体在画外”，并同步核对该镜构图字段，避免正文与自动追加要求互相冲突。不要用增加剧情中不存在的封口或束缚来表达角色处境；对白镜头尤其要核查嘴部无遮挡。画外肢体只记录为未展示，不声称其细节已验证。

### 真实返修验证补充（2026-11-02）

- 固定世界坐标的场景模板新增一个真实通过实例：正视、反打、俯视与侧视的开口和窗户位置可对应，俯视门移到错误墙面的问题已修正。与先前客厅实例合计覆盖两类空间，仍逐图检查，不宣称所有空间稳定。
- 四个近景/手势返修实例保持高低人物关系，并消除坐椅或躯干绳索；两个客厅镜头分别恢复正确背景墙与坐姿近景。明确画内主体、裁切边界、视线及画外状态，比仅堆排除词更便于核验。
- 正式白底道具新增连续绳索和金属容器两例：两端/提梁/连接处完整，参考图的排版文字未带入。模型仍须逐件核验材质、结构及数量。
- 生成前核对静帧与首帧字段是否冲突，例如不能同时要求“刚开始解开”与“已经全部解开抱起”。将结束动作留在结束状态，静帧固定一个可执行瞬间。

### P-006 补充：局部束缚与动作瞬间（2026-11-02）

状态：两个全身/中全景返修实例，以及一个俯视受困镜头和一个解结中近景，经真实前端逐图检查通过；属于本轮创作测试选用，仍需逐镜复核。

可复用要求：先写身体落在何种支撑面、左右高低关系和当下动作，再将束缚位置限定为“前方并拢的双腕”和“并拢的脚踝”两处独立短绳；明确胸腹衣服轮廓完整、腕踝之间不连绳。单写“被绑”曾生成胸腹环绕绳，单写“倒地”曾生成自由双手撑地。

返修核对同时检查道具操作和时间：持容器双手与水流方向可解释；点火瞬间只有手中微小火苗，环境火势留给下一镜；解结图保持手部接触和绳结位置，完全解开及抱持写入镜末状态。裁切掉的脚部只记为画外，不能据此认定脚踝细节已验证。

### P-006 补充：控制画内主体的两次真实验证（2026-11-02）

- 纯道具微距返修：将构图和生图正文同时限定为“小型物证、短段挂绳、捏绳的手指，背景仅冷色空间光斑”。真实回图保留物件结构与持握，没有再把画外受困人物、封口或胸腹绳索带入。一个适用实例通过，不扩展为所有道具的稳定保证。
- 冲入房间的低机位返修：第一版虽保留门口主体，却在前景加了错误躯干绳索，明确退回。后续将前景限定为左下少量虚化头发和肩缘，小于画面六分之一，躯干、手腿全部在画外；主体保持门口向前的动作。新回图符合这些可见约束并通过测试选用，画外束缚仍不能宣称可见验证。
- 两例均先在导演台保存构图与提示词，再显式载入已保存要求、重新准备和确认生成；旧失败图与原任务保留。避免只修改一处提示词而让自动追加的构图要求继续冲突。
