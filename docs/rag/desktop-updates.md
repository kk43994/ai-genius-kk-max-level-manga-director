# 桌面自动更新

版本：0.3.0-preview.6，2026-11-03。状态：LibTV 授权修复已随公共源与两端安装包发布；实际 preview.5 更新器读取公网、下载与哈希校验通过，客户设备安装升级另行验收。详见 [发布记录](../updates/20261103-1235-desktop-auth-update.md)。下文保留各次历史验证。

用户要求开放自动更新。新版 AssetLab 启动时自动检查，之后每 4 小时检查一次；用户可关闭或手动检查。仅读取固定官方 HTTPS 发布源 `https://kk666.best/asset-lab/release.json`，只接受对应产品、渠道、系统和官方 downloads 目录，不跟随重定向，不发送用户凭据。更新包自动下载到独立 updates 目录，校验文件大小和 SHA-256；不降级，校验失败不安装。

安装前点击“保存并安装更新”。前端先保存草稿并核对会话、授权、写入、任务和下载状态，服务端再检查当前工作区的运行任务；未完成任务阻止安装。独立安装辅助进程等待旧进程自然退出，不强制终止。Windows 启动已校验安装程序并在成功后打开新版本；Mac 打开系统安装窗口，仍需完成系统安装步骤。程序与工作区目录分开，Windows 既有版本目录保留。源码运行只检查/下载，不运行安装器；独立 ManjuWorkbench 产品不套用 AssetLab 更新源。

安装包入口默认开放图片制作服务，但创作仍依赖用户账号的官方创作授权，每批提交仍有账号、费用和参考确认；视频/音频继续关闭。开发源码入口仍需显式图片开关。不能把更新检查、安装器打开或源码推送写成安装完成。

旧客户端没有更新器，无法靠服务器开启标记获得更新功能。需先覆盖安装一次包含更新器的版本，之后才有自动检查/下载入口。2026-11-02 实际读取公开发布源仍为 0.2.3-preview.1，`automaticUpdates=false`；这是当时在线状态，后续发布必须重读确认。

验证：更新器 7 项合成测试覆盖下载复用、拒绝降级、来源与平台校验、损坏文件、安装前二次哈希校验、开关持久化、等待旧进程退出及打包入口图片开关；1 项真实 HTTP 合成测试覆盖会话、CSRF 和运行任务门禁。新增前端 3 项回归覆盖工作区卸载清理、运行任务阻止安装与检查失败显示。真实 Chrome 已看到默认勾选的自动检查开关，手动检查返回公开旧版本并正确拒绝降级。未执行真实 Windows/Mac 安装，不宣称客户自动升级验收通过。本地安装候选已构建，仍需逐系统安装、升级和数据保留验收，然后发布固定版本包及 manifest。

实现：`local_client/updater.py`、`install_update.py`、`launch.py`、`scripts/browser/local-updates.mjs`。设置与安装包在 `<instance>/updates/`，与项目数据库、媒体和加密密钥分开。旧版本恢复使用对应历史安装包；勿覆盖项目数据目录。

Windows 打包清单显式包含 `updater.py` 与 `install_update.py`；Mac/Windows 构建来源记录与实际默认图片开关、自动更新能力一致。此为打包修复，仍须核对实际产物及安装升级。

2026-11-02 已从源码 `5923ea356a8e39dd30ec35a0005f46509e560ff1` 构建 Windows ZIP/EXE 与 macOS arm64 PKG。Windows ZIP 624 个清单文件逐项 SHA-256 一致，两平台更新器和安装辅助模块已包含。Mac 冻结运行时在隔离空工作区真实启动，Chrome 显示新版首页、默认开启的自动更新和旧版拒绝降级，随后从前端正常退出。没有运行系统安装器或 Windows 程序，未证明覆盖升级或数据保留，也未发布公开下载源。构建摘要在仓库外 `../evidence/desktop-package-preview4-checks.json`。

## 新版本浮动提示

启动检查发现更高版本时，在右上方显示版本号和下载状态；包校验完成后可保存并安装。稍后提醒只隐藏当前页面的该版本，手动检查可重新显示；不会抢占输入焦点。弹层与底部安装按钮共用保存和运行任务检查。旧公开 0.2.3-preview.1 的已解包源码确认 local-client 分支未接入检查，必须先覆盖安装一次，不能通过服务端标记补齐已分发的程序逻辑。
