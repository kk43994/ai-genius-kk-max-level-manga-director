# 用户确认的创作流程

状态：已确认产品要求；候选版主线与交付范围已实现，真实前端闭环验收正在进行。来源：2026-11-01 本项目用户语音确认。适用：0.3.0-preview.1 及后续修复。

## 主线与页面归属

1. 剧本分析：导入所需集数，保留原文；由 AI 提取时间、地点、人物、事件、场次、台词与关键道具。人工核对，创作建议与原文事实分开。
2. 风格探索：MJ 抽人物长相、场景风格与道具候选。人选图并确认本剧统一美术规范。生成、重抽、选用不同义。
3. 资产制作：沿用已选风格，Image2 制作人物四视图、场景多视图、道具白底主视图。人物四视图为正面全身、侧面全身、背面全身、头部特写；场景为正视、反打、俯视、侧面。Nano 是资产内部的可选精修，不占一层主导航。
4. 导演编排：左侧人物／场景／道具资产库，搜索、点击引用或拖入镜头。保存真实档案、状态、固定图片版本的关系，并编排动作、台词、摄影机和连续性。
5. 审核交付：审核就在图片旁；汇总页处理待审项与下载。最终视频仍保持暂停，不把图板预演说成视频。

## 人工决定与按钮

每张候选图旁有明确动作：选用此张作为人物形象、选用此张作为本剧风格、生成角色四视图、保留这版四视图、重新生成四视图、生成场景多视图、生成道具白底图、加入当前镜头。

每屏只有当前阶段的主要动作。图片先于长表单，提示词与高级参数按需展开。失败先查询原回执；重新生成必须显式发起并经过既有费用确认。旧稿、旧图与审核记录保留，绝不因整理页面而自动批准素材。

## 实现映射与验收

入口：`frontend/workflow/controller.js`。生成：`production-generation.js`。导演引用：`production-references.js`、`production-board.js`。状态与准备：`backend/analysis/production.py`。

验收应覆盖导入→分析→选风格→规范资产→引用镜头的浏览器路径；合成数据检查不能代替真人选图、真实收费调用或正式安装验收。逐项完成状态见版本记录。

本轮新增验收要求：只通过工作台前端上传剧本、授权、提交任务、查看返回、选用、编排与导出；卡点可以修复源码和服务后重试，但不得直接调用后台替用户完成步骤。真实目标是可用的分镜图与分镜脚本。演示服务器有意禁用生成，不能作为真实生成的验收环境。

DOCX 新项目导入必须引入 `guide.js` 的 `prepareIdentity`，以文件内容生成幂等编号；本轮已补齐漏导入。Chrome 自动文件选择注入若卡在读取，需区分浏览器上传能力和产品异常；原生系统文件选择框也是正常前端路径。
