# 剧情卡片与无限画布

日期：2026-11-03。状态：preview.6 源码开发版，尚未公开发布安装包。

## 用户要求

用户指出剧本分析的纯文字难以看懂，要求直接生成一眼可读的卡片；随后确认卡片适合放在无限画布中。结果展示优先以场次为单位，把在场人物、地点、时间、剧情、台词放在同一张卡中，保留原文核对与手动修改。

## 实现

- `frontend/workflow/story-cards.js` 将已返回分析转为语义卡片，不重新调用 AI，不推断新剧情。按场次 order 排序；人物保持固定颜色；仅被提及者与实际在场者分开；闪回、梦境、转述等保留标记，时段枚举显示中文。原文不符及关联疑点在相应卡片提醒。
- 已有合格已选分镜时，复用 `overviewShots` 的当前方案、归属与交付覆盖核验，按场次展示最多三张代表图；没有图片时展示明确标注的人物示意。示意图不等同于已确认人物形象，也不冒充新生成的分镜。存在未保存分析修改时暂不装饰旧方案图片。
- `story-canvas.js` 在 DOM 无限画布内按剧情顺序连线，人物卡在下方；支持空白拖动、触控板平移、Ctrl / Cmd 加滚轮缩放、单卡拖动、键盘移动、场次定位、一览全剧、自动排列和专注模式。图卡依旧可点击展开原文台词。
- 卡片位置与视角只保存到当前浏览器、本站租户与 API 挂载路径、分析任务隔离的本地存储。移动布局不改变剧本顺序、不修改生产方案、不发出供应商请求。损坏的布局缓存退回默认排列。此项不是跨电脑布局同步。
- “修改本场 / 修改台词 / 查看人物”展开对应原有编辑字段；“对照原文”定位对应行。进入编辑或原文时退出专注模式，避免全屏画布遮挡目标。保存仍走原核对与版本机制。
- 模型/回执/字段明细收在详情中，分析阶段侧栏收起给画布空间。导演制作画布保持原功能，默认不在分析页展开。

## 验收与限制

真实 Chrome 已加载项目四场卡片和现有合格分镜，专注画布与剧情连线可见；没有重新选用图片或发起收费调用。合成前端使用真实工作流控制器，实测拖卡片、空白平移、缩放、自动排列、展开两条原文台词、退出专注进入编辑、保存后卡片同步、定位原文三行；模拟保存后的 AI 调用计数保持为一。

全量检查及截图路径见 preview.6 版本记录。真实剧本和截图保留在仓库外，不写入知识库。未执行真实客户的分析内容修改；没有构建/发布安装包，也没有宣称其他电脑已升级。

## 恢复

本轮无后端或数据库迁移。可独立 revert 此次前端与文档提交；原剧本、图像、审核和任务不变。可忽略本机 `asset-lab:story-canvas:v1` 布局缓存，无须删除客户数据。
