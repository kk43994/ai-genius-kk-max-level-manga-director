# 图片模型、并发与素材引用

适用版本：0.3.0-preview.4。更新：2026-11-02。状态：开发与真实前端验收中。

## 用户确认范围

本轮先完成图片创作功能，视频和音频后续接入。MJ 主要用于探索人物和场景的美术方向。图片模型由用户下拉选择，默认 Lib Image 2.5 Pro；人物主多视图确认后再派生状态，不因模型可选而取消身份基准。不要把模型选择重新混入制作阶段导航。

## 官方模型证据

2026-11-02 从工作台前端触发官方 `search_models(nodeType=image)`，实际返回列表位于 `matches`。本次可见 28 个图片模型。默认模型经过 `get_model` 校验：Lib Image 2.5 Pro = `lib-image-2.5-s`；Fast = `lib-image-2.5-f`；Lib Image = `lib-image-2`。这三项是不同目录记录，不能把旧 Lib Image 的验收冒称为 2.5 Pro。

前端使用实时目录，不把这份日期快照当永久可用清单。参数取自 `inputContract.parameterSchemas.generate`；Pro 的质量、分辨率、背景、画幅和每组张数已在真实前端显示，当前官方默认 medium / 2K。每个任务保存自己的 `modelId`，准备时解析实际 modelKey 与契约摘要，提交时再核对；旧任务继续按原快照恢复。

## 同一物料多组并发

每批 1 至 8 组，每组张数由模型契约控制，目前任务上限 4 张。第一次准备建立档案，后续组以最多 3 个并行请求准备；一次确认明确组数、总张数与总费用状态，然后最多 3 个并行提交请求。官方返回任务后可继续准备其他组，无需等上一组出图。

每组有独立且稳定的准备键与任务回执，结果分别显示。一个失败不会丢掉同批其他组的回执；未知提交不重发新任务。显式新增抽卡与恢复旧任务分开。真实 Chrome 前端已完成同镜两组 Pro 提交与回图，均为 high / 2K / 9:16、每组一张；逐图查看后选用一版，另一版保留历史。这只证明该镜头两次成功，不代表模型在所有题材上稳定。

## 参考图

已审核人物主图为第一张身份来源；补充参考独立标注为画风、外形、场景空间、道具或构图。所有参考保存到任务中的固定图片版本及字节摘要，不依赖会变化的当前下拉选项。额外参考不能顶替必需人物主图，撤销参考审核会使下游失效。

上传参考不写入剧本制作清单，单独作为项目参考图片保存；先看图保留，再加入生成。最多 8 MiB 的 PNG/JPEG/WebP，按当前账号与空间隔离；不会把参考图片当已完成的正式资产或导出物。

LibTV 素材库使用官方 `search_assets` / `get_asset`。实测个人库查询也要求项目上下文，因此传入已保存并核实的原账号官方项目映射；读取库时不会新建远端项目。素材图片固定版本后导入项目，原库内容不改动。真实前端已验证个人库列表、单项图片预览、固定版本复制入项目和看图保留。详情图片经服务端校验后以缩略图显示，不放宽页面 CSP；原始图片地址不暴露为前端导入依据。团队库与完整分页尚未接通。

## 镜头与生图草稿同步

导演台已保存镜头要求与当前生图草稿不同时，保留手工草稿，并显示“使用已保存镜头要求”。用户显式载入后带入当前构图、首帧和连续性，保留模型参数与其他选择。未保存的镜头修改须先保存；不静默覆盖手工提示词。

## 长时间等待

官方 SSE 的 keepalive 只表示连接存活，不能重置单次请求的等待期限。`OfficialHTTP` 同时保留 socket 超时与按 monotonic 时钟计算的总等待上限，超时返回受控错误，不自动重试收费调用。相关认证协议测试 93 项通过。

## 官方引用显示转换与中断恢复（2026-11-02）

真实参考生图预检发现：发送给官方的 `{{Node 节点编号}}`，在 `read_project` 中会显示为 `{{Image N}}`。因此先核验实际入边和 `imageList` 顺序，再仅在比较时把该显示标记映射回已核实的节点编号；其余提示词、模型、参数仍必须完全相同。发送请求继续使用稳定节点编号，不使用猜测的 Image 序号。

节点已建但未记录收费调用的中断任务，查询时只读取原节点。只有原上传、节点回执、未生成状态全部核对一致，才标为 `REFERENCE_SETUP_STOPPED` 并提供显式重新准备入口。已有收费调用或未知回执仍恢复原请求，不自动重发。此修复的合成测试不代表真实回图质量通过。

## 跨镜头批量准备（2026-11-02，真实验收中）

导演台生图区增加“批量准备缺图镜头（最多 8 镜）”：复用用户当前选择的模型参数，各镜使用各自已保存提示词和固定参考，每镜一组。只包含参考齐全且从未制作的镜头；已有候选、待确认、失败或回执不明的镜头均交回逐镜处理，批量入口不隐式重抽。逐镜读取最新清单版本后建立档案，最后一次确认清单、各镜参考、提示词和总张数，再以最多 3 个提交请求并发处理。准备失败保留原记录并列明，已准备成功的仍可确认。合成回归验证过滤、8 镜上限和失败不重试。真实前端一批 8 镜均准备成功，确认后均获得官方排队回执；尚待逐张回图审核，不把排队当成出图成功。

## 部分交付不阻断已选图片继续制作

真实前端已从原任务恢复 3/4 张候选并逐图保留一张，第四张交付仍待核对。已知回执且已有归档输出的 PARTIAL_DELIVERY 不再锁住同物料的后续制作按钮，用户可用已审核来源制作正式资产；原任务恢复按钮、数量与错误继续显示。未知提交、缺失回执及未审核来源仍禁止越过各自门禁。前端回归覆盖部分输出放行、同档案另有未知提交仍阻止、缺回执仍阻止；不自动准备或重发任何生成。


## 显式批量返修

导演台增加“批量准备待返修镜头（最多 8 镜）”。只纳入当前归属下最新分镜图已退回、有对应已完成任务输出、全部参考已固定且没有任何待确认/处理中/失败/未知任务的镜头。已有有效保留图也排除。采用每镜已保存要求，不替换手工生图草稿；逐镜准备后展示新一批清单与费用，用户确认才提交。该入口明确创建新的返修生成，不冒充恢复原收费任务。回归覆盖未知任务、准备中、失败、待审新图、已保留图、跨账号图片与缺失回执的排除；真实前端已筛出 7 镜，逐项展示保存后的提示词与固定参考，已统一确认提交；新回图仍待逐张视觉审核。
