# 漫剧画布制作流水线 · Goal 实施与验收计划

开始：2026-11-03。状态：执行中。分支：`codex/creator-workflow`。基线：`a62e573`，preview.6 开发源码；公共安装包 preview.5。勾选表示该项已有相应实现和验收证据，不把准备、排队、合成回图或代码提交当作真实生成质量通过。

## 已确认目标

每部新漫剧使用同一套固定制作框架。AI 根据剧本填写剧情和物料字段，程序负责卡片、布局、依赖和流程。分析结束立即铺开占位卡。用户在同一画布中先探索并确认全剧美术标准，再制作人物、场景、道具和分镜；点图选版本，修改和重抽就在当前对象旁。

全剧美术试做包含人物风格、场景风格和人物入景试镜。MJ 探索人物与场景风格；Image2.5 Pro 默认用于正式试做和资产/分镜生产。用户可在官方图片模型目录中切换模型。人物共享画风但保留各自长相；人物主多视图先确认，之后派生剧情状态。Nano 是原图旁的可选保真处理。

## 逐项清单

### 0. 基线与实施边界
- [x] 读取当前代码、AGENTS、RAG 与历史迭代；确认已有画布和生成通路可复用。
- [x] 建立本计划、验收定义与任务顺序，启用 Goal。
- [x] 将计划加入版本/RAG 索引并提交基线计划。

### 1. 固定框架与占位卡
- [ ] 定义一个版本化的制作模板：美术试做、主资产、剧情状态、剧情/分镜、审查交付。
- [ ] 分析后自动呈现人物、场景、道具与剧情占位卡；未知内容明确待补，不伪造图像或镜头数量。
- [ ] 固定字段与布局由代码决定；角色/场景/镜头数量随剧本变化；已有生产方案补入原卡片。
- [ ] 默认布局先展示美术试做和主资产，再显示各场剧情；保留平移、缩放、定位与布局恢复。
- [ ] 验收：无图片、仅分析、已有制作方案、旧项目四种状态都可读；刷新不重复建档或调用 AI。

### 2. 同一画布上的创作面板
- [ ] 点击人物/场景/道具/镜头卡，原地打开对象面板，保留画布位置；取消/返回恢复原对象。
- [ ] 面板复用现有选图、模型、提示词、参考、并发组数、任务确认和版本窗口。
- [ ] 精简主导航；旧“风格探索/资产制作”入口和保存偏好兼容进入对应画布区域。
- [ ] 长参数默认折叠；图卡只有当前主动作，候选点图选择，等待中仍能浏览其他对象。
- [ ] 验收：对象切换无串图/串提示词；未保存草稿保留，键盘关闭和窄屏可用。

### 3. 全剧美术试做与标准
- [ ] 独立试做区固定三槽：人物风格样板、场景风格样板、人物入景试镜；支持候选比较与重抽。
- [ ] 先用 MJ 探索，再以 Image2.5 Pro 少量试做；引用类型区分风格、角色身份和场景空间。
- [ ] 试镜带上选定人物和场景图，通过既有准备/费用确认通路生成，结果由人确认。
- [ ] 一次明确确认保存整套美术标准：固定图片版本、短规范、提示词/参数来源与标准版本。
- [ ] 后续任务自动继承适用的已确认标准；旧单图标准兼容保留，不要求重做已有项目。
- [ ] 修改标准显示影响范围并保留旧版本/任务；不自动改写已准备的输入或重发生成。
- [ ] 验收：缺项、跨项目/账号、失效参考、并发版本冲突不能误确认；确认新标准不修改原图。

### 4. 主资产与剧情状态
- [ ] 人物：主形象 → 主多视图 → 剧情状态多视图，前一步已选图片自动成为明确引用。
- [ ] 场景：主图 → 正视/反打/俯视/侧视 → 日夜或剧情变化，位置结构有固定依据。
- [ ] 道具：白底定型图；当前剧本所需道具可补入制作清单。
- [ ] 试做样板属于本剧对象时可明确沿用，避免重复制作；同名对象不自动合并。
- [ ] 验收：主图未确认的状态不能冒充完成；人物身份与全剧画风分别引用，已有素材原位回填。

### 5. 分镜生产与按依赖并发
- [ ] 镜头卡使用固定字段：场次/人物/动作/台词/构图/首尾状态/固定参考/图片。
- [ ] 所需素材齐备的镜头可独立准备，不必等待全部资产完成；缺项可直达对应卡片。
- [ ] 从画布明确选择一批待制作镜头，并发准备/提交，展示任务状态、实际张数和费用。
- [ ] 返回图片补入原卡，候选不自动选用；已提交/未知回执从原任务恢复，不隐式重发。
- [ ] 验收：混合齐备/缺项/处理中/待选的镜头不会误批量生成；其他对象草稿不被覆盖。

### 6. 连续性审查与复用
- [ ] 同页按剧情顺序看图片、描述、原文台词和前后状态，支持跳转下一待处理。
- [ ] 增加静帧按时长播放的图板预演，暂停可回到当前镜头；不冒充视频生成。
- [ ] 新项目默认套用固定流程与字段，当前项目美术规范独立；稳定提示词可作为有来源的模板复用。
- [ ] 提示词规范区分待试、单次通过和可重复验证；记录原图/模型/参数，不声称模板能保证质量。
- [ ] 验收：仅当前已选有效图参与交付；未保存修改提示明确，旧版本和原文修正保留。

### 7. 验收、版本与交付
- [ ] 运行与变更对应的单元/集成回归，以及 `scripts/check_all.py` 全量检查。
- [ ] 本地 Chrome 合成项目从空画布走过试做、确认标准、主资产/状态、分镜与预演。
- [ ] 本地 Chrome 真实项目验证原数据、草稿、图片、选用和导航兼容；只经前端操作生成。
- [ ] 真实 LibTV 授权与目录恢复后，通过前端完成代表性试做；费用/回执/出图/人工质量分开记录。

## 设计依据

- 用户确认的流程与页面交互为本计划的主依据。
- [Disney Visual Development](https://disneyanimation.com/process/visual-development/)：依剧本和导演意图探索人物与世界的美术方向。
- [Disney Story](https://www.disneyanimation.com/process/story/)：从粗分镜逐步细化叙事、表情、节奏和构图。
- [Toon Boom Storyboard Timing](https://docs.toonboom.com/help/storyboard-pro-25/storyboard/timing/about-timing.html)：调整分镜时长并播放预演以核对节奏。

## 恢复原则

每阶段可独立回退 UI；扩展数据字段必须兼容旧标准和旧项目。保留不可变任务输入、回执、图片、审核和用户草稿，避免通过删数据解决兼容问题。源码更新、公共安装包、其他电脑自动更新、真实供应商质量分别验收。
