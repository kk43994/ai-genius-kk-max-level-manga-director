# AI 漫剧制作方案

在已完成的 AI 剧本分析之后进入“02 制作方案”。使用当前已选择、已授权的 LibTV 文本模型设计物料状态、场次空间、表演、分镜和两类镜头提示词。每次设计固定原文版本、原分析、模型、风格和账号/空间；服务端持久化请求与官方回执，未知提交不重发。

基础物料包括实际出场的角色、地点和关键道具。每项物料具有独立状态、原文引用和单一状态资产图提示词。原文没有限定的外貌、服装、材质与摄影选择列为创作建议。每镜独立关联物料状态、原文事件与原文台词，保存叙事目的、构图、机位、表演、首尾状态、静帧提示词、视频动作提示词、声音与连续性要求。

本地程序只检查结构、逐字引用、编号和关联完整性，不代替 AI 提取或编造剧情。它要求全部场次和事件覆盖、每句原文台词恰好关联一次、禁止将仅被提及的人物安排出镜。镜头允许全片编号或按场重置，画面显示按数组播放顺序统一编号。

方案不是正式视频。预演按建议时长播放文字图板；只有同账号/空间的当前、已审核素材可作为参考缩略图。系统试读是可选的浏览器辅助声音，不是最终角色配音。人工可调整物料、状态、原文引用、画面、表演及提示词，保存采用版本校验并保留 AI 原结果。核验失败不会隐藏已返回的结构化方案：公开状态为 `needs_review`，返回 `draftResult` 和带字段路径、原文对照的 `validationIssues`；手动修改保存到独立 `production.reviews`，原任务记录保持不变。未全部改完可以先保存，但加入资产清单仍要求引用与关联核验通过。

物料需勾选核对后加入现有资产清单草稿，再手动保存。加入只新增稳定编号，不覆盖已有条目或自动批准图片；同名条目使用编号区分。全局美术风格不因返回方案而被自动覆盖。

## API

- `GET/POST /projects/{projectId}/scripts/{scriptId}/production`：最新方案 / 明确确认费用后开始。为兼容现有分析任务读取形状，GET 返回 `{analysis: job|null}`。
- `GET /production-jobs/{id}` 和 `POST .../refresh`：读取/继续查询原回执。
- `POST .../revalidate`：内容核验失败后，使用更新的核验器重新读取同一原结果，不新增模型调用。
- `POST .../repair`：`{confirmSpend:true}`，明确增加一次 AI 调用修正原结果；同任务最多一次，保留原回执。不修复或重发提交结果未知的任务。
- `POST .../retry-rejected`：只处理官方明确拒绝、未提交的重名请求。
- `GET .../plan`：返回只新增物料的草稿候选，不写入现有计划。
- `PUT .../review`：`{expectedVersion,expectedEditVersion,result}`，保存完整人工调整并仅在本机核验。格式有效的待核对草稿也能保存，原始返回可独立查看；不发起任何模型调用。
- `PUT .../edits`：`{expectedVersion,shots}`，只允许时长、表演、静帧/视频提示词调整。

## 2026-11-01 验证边界

本地 Chrome 取得的当前 004 号官方结果包含 6 项物料、11 个状态、7 个镜头。原生成及一次 AI 修正共 2 次调用，仍有 3 处引用缩写或漏掉原文注释。本次在 Chrome 手动编辑第一处，保存后刷新验证还剩 2 处；再通过原文对照按钮修正剩余两处并保存，读回状态 `ready`、问题数 0、人工修订版本 2。原始任务内容 SHA-256 未改变，调用次数仍为 2。只修正引用，不代表分镜创作内容已经审核，不自动入库或生成图片。

38 项分析单元测试、95 项集成测试和 71 项 Node 测试通过。覆盖待核对草稿可读、部分保存、无模型追加调用、原文不变、租户隔离、版本冲突与旧分镜编辑兼容。

图片制作、审核和导出仍走已有流程；本功能没有开启最终视频生成，也没有自动批准既有图片。本地构建不代表 Windows/macOS 安装包或公网下载站已更新。
